# Cascade — Design-Quality Audit (read-only)

**System:** Deep Current design system. Tokens in `packages/ui/styles/tokens.css` (note: the brief said `src/tokens.css`; the file actually lives under `styles/`). Shared primitives (`.btn`, `.card`, `.panel`, `.pill`, `.tag`, `.chip`) are defined in that same token file; React wrappers live in `packages/ui/src/*`.

**Scope:** `apps/web/app/**` UI + `packages/ui/src/**`. Every claim below was grounded in the actual code (file:line). Findings are grouped **High → Medium → Low**; each is tagged with its audit dimension `[1 Spacing] [2 Icons] [3 Alignment] [4 Type] [5 Consistency] [6 States] [7 Elevation]`.

**Out of scope (per instructions):**
- `apps/web/app/admin/**` — excluded.
- `packages/ui/src/shell/WorkspaceSwitcher.tsx`, `apps/web/app/(app)/_components/workspaceLogos.ts`, `apps/web/public/logos/*` — **concurrent edits by another session**; not audited.

**How to use:** this is a review list, not a change set. Nothing was modified. Check items off as you triage.

---

## Top themes (read this first)

1. **No spacing scale exists.** `tokens.css` has type, radius, shadow, color, and motion scales but **zero `--space-*` tokens** — so all spacing is hardcoded (595 `px` values in padding/margin/gap). This is the root cause of the uneven padding/rhythm across screens.
2. **The Phase-4 surfaces (billing, onboarding, templates, sequencers) are the least polished** — two are outright broken (`--fs-md` invalid, seat-bar "full" class never matches), and they carry most of the off-scale type, ad-hoc rings, and missing error states.
3. **Icons are inline-duplicated with drifting stroke weight.** ~30 hand-inlined SVGs, no shared icon module; the checkmark alone ships at 6+ weights (2 → 3.2). This reads as several icon libraries in one app.
4. **The primitives are healthy; the bespoke containers are not.** Buttons/inputs/pills/dialogs are used consistently, but "card"-like and "icon-button" and "link-button" containers are re-implemented per file with divergent radius/shadow/size.

## HIGH — looks broken or clearly unprofessional

- [x] **[1 Spacing] — DONE (Batch 1).** `--space-*` scale (`0 2 4 6 8 10 12 16 20 24 32 40 48 64`, px) added to `tokens.css`; card/panel padding consolidated to a two-tier system (`--space-20` content / `--space-16` gallery+panel); ~595 px values tokenized across 40 files via the approved rounding map. Green: typecheck / 185 tests / web build. Adversarial verify flagged 5 subtle spots to eyeball rendered — 2 medium (Dialog header↔close clearance `44→40`; integrations link-button height vs sibling `<Button sm>`), 3 low — to fix as specific spots after review. _Original finding below:_
  **[1 Spacing]** `packages/ui/styles/tokens.css` (absent) — **No spacing scale.** The token file defines `--fs-*`, `--r-*`, `--shadow-*`, `--dur-*` but no `--space-*`, so every gap/pad is a raw px literal (595 occurrences). Card/panel padding alone ranges across `14px` (onboarding `.tmpl`), `16px` (templates `.card`, billing `.planCard`), `16px 18px` (onboarding `.explainer`), `20px 22px` (billing `.card`), `clamp(22px,3.4vw,34px)` (onboarding `.card`) — no shared step. _Why:_ without a scale, spacing drifts and vertical rhythm never lines up between screens. _Fix:_ add `--space-1…-8` (e.g. 4/8/12/16/20/24/32/48) and adopt in the primitives + module CSS.
- [ ] **[4 Type]** `apps/web/app/(app)/onboarding/onboarding.module.css:122` (`.lede`) and `apps/web/app/(app)/tables/[tableId]/_components/csv/csv.module.css:101` (`.dropTitle`) — **`font-size: var(--fs-md)` references a token that does not exist** (scale is hero/h1/h2/h3/h4/body/sm/xs/2xs). The declaration is invalid, so the onboarding lead paragraph and the CSV drop-zone title silently fall back to inherited size. _Why:_ primary copy renders mis-sized/flat; reads unfinished. _Fix:_ `var(--fs-body)` (or `var(--fs-h4)` for the drop title).
- [ ] **[6 States]** `apps/web/app/(app)/billing/page.tsx:180` — **Seat-bar "full" state never renders.** `<i className={seatsFull ? 'full' : ''} …>` sets a literal string, but the rule is the CSS-module-scoped `.seatBar i.full` (`billing.module.css:110`) which compiles to a hashed class. The DOM's `"full"` never matches, so the amber `--st-empty` bar stays brand-green at 100% even while "Seat limit reached" shows beside it. _Why:_ the warning state contradicts itself. _Fix:_ `className={seatsFull ? styles.full : ''}`.
- [ ] **[7 Elevation]** `apps/web/app/(app)/templates/templates.module.css:39-60` — **Templates gallery cards have no resting shadow.** `.card` (rendered as a `<button>`, `templates/page.tsx:150`) sets surface/border/radius but `box-shadow` only on `:hover` (`--shadow-3`). Its own loading skeletons use the shared `<Card>` (`--shadow-2`), and the sibling **Tables** gallery cards are elevated — so cards visibly "un-lift" when data loads, and two adjacent gallery screens read differently. _Fix:_ add `box-shadow: var(--shadow-2)` at rest, or compose the `.card` primitive.
- [ ] **[2 Icons]** Checkmark glyph (`M20 6 9 17l-5-5`) ships at **6+ stroke weights**: `verify/page.tsx:13` (2), `Sidebar.tsx:132` (2.4), `csv/ImportWizard.tsx:119` (2.4), `billing/page.tsx:24` (2.6), `views/ViewSwitcher.tsx:55` (2.6), `onboarding/_components/Stepper.tsx:10` (3), `onboarding/_components/TemplatePicker.tsx:12` (3.2), `packages/ui/src/Input.module.css:37` (3). _Why:_ the most-repeated glyph in the product has no single weight — "done/selected" looks heavier on the onboarding stepper than in the sidebar or billing, so each screen reads as a different design language. _Fix:_ one shared `<CheckIcon>` at `strokeWidth 2`, sized by CSS; delete the inline copies.

## MEDIUM — visible inconsistency / off-token

- [ ] **[4 Type]** Off-scale font-size literals bypass the `--fs-*` scale, concentrated in Phase-4/chrome: `billing.module.css:74` `.planNow 1.5rem`, `:157` `.planPrice 1.7rem` (+ `font-weight:800`, heavier than the 700 display scale), `:152` `.planName 1.05rem`, `:219` `.packCredits 1.25rem`; `shell/shell.module.css:25` `1.12rem`; `Alert.module.css:18` `12px`; `enrich/credits.module.css:23` `2rem`; `enrichment.module.css:179` `16px`; `views.module.css:26,115` `10px`. _Why:_ the largest text on the billing page bypasses tokens; sizes won't scale with the system. _Fix:_ map each to the nearest token (`--fs-h2`/`--fs-h3`/`--fs-h4`/`--fs-sm`/`--fs-xs`).
- [ ] **[2 Icons]** GridToolbar mixes stroke weights in one control cluster: `tables/[tableId]/_components/GridToolbar.tsx:61,68` (2.2) sit beside `:75,83,98,105` (2) at the same 15px. _Why:_ adjacent toolbar buttons have visibly different line thickness. _Fix:_ normalize `.btnIcon` glyphs to `strokeWidth 2`.
- [ ] **[2 Icons]** Same glyph, different weights across screens: **Plus** `Sidebar.tsx:71` (2) vs `GridToolbar.tsx:68` / `views/ViewSwitcher.tsx:62` (2.2); **Arrow-right** `automations/_components/InboundWebhookDialog.tsx:236` (1.8) vs `csv/ImportWizard.tsx:112` (2) vs `templates/page.tsx:68` (2.2); **Trash** exists as two different paths (`ColumnConfigFields.tsx:49` etc. vs `InboundWebhookDialog.tsx:259`) at weights 2 / 2.2 / 1.8. _Fix:_ shared glyphs at one weight.
- [ ] **[2 Icons]** **No shared icon module** — ~30 glyphs are hand-inlined per file; several are byte-identical duplicates (kebab `DotsIcon` in `tables/page.tsx:37` & `members/page.tsx:79`; people glyph in `Sidebar.tsx:78` & `members/page.tsx:91`; "lock" in `automations/page.tsx:92` & `integrations/page.tsx:53`, with a *third divergent* lock in `billing/page.tsx:31`). _Why:_ copies drift over time (the lock/bolt already have). _Fix:_ extract `packages/ui/src/icons` and import.
- [ ] **[2 Icons]** Solid-fill icons interleaved with stroke-outline icons on the same surface: GridToolbar `IconRun`/`IconSparkle` (`fill="currentColor"`) among outline icons; billing pairs a stroke lock with stroke checks. _Why:_ reads as two icon libraries. _Fix:_ commit to the outline family (a filled play triangle is the one defensible exception).
- [ ] **[2 Icons]** Page-header glyph size drifts: `width="26"` on `providers/page.tsx:36`, `integrations/page.tsx:53`, `billing/page.tsx:31` vs `width="24"` on `automations/page.tsx:101,109`, `integrations/page.tsx:62`, all at `strokeWidth 1.8` (lighter than the app's 2). _Fix:_ standardize header glyphs to one size + weight.
- [ ] **[5 Consistency]** **`.linkBtn` re-declared in 4 files** (`members.module.css:104`, `automations.module.css:100`, `integrations.module.css:102`, `providers.module.css:68`) with divergent disabled behavior: `cursor:default` (members, automations) vs `not-allowed` (integrations) vs **no `:disabled` rule** (providers). _Why:_ the same "Disconnect/Revoke" text button behaves differently per screen. _Fix:_ replace with `<Button variant="ghost" size="sm">`.
- [ ] **[5 Consistency]** **Icon-button re-implemented ~6×** at 3 sizes / 3 backgrounds: `enrichment.module.css:47` (26px/surface-2), `ai-column.module.css:126` + `column-tools.module.css:122` + `views.module.css:232` (30px/surface-2), `automations.module.css:221` (30px/transparent), `integrations.module.css:267` (28px/transparent), `views.module.css:359` (30px/surface). _Why:_ icon buttons don't line up in size or fill between panels. _Fix:_ one shared `.iconBtn` primitive.
- [ ] **[5 Consistency]** **Destructive-hover border uses two conventions:** softened `color-mix(… var(--st-failed) 40%…)` (`members.module.css:126`, `automations.module.css:121`, `integrations.module.css:123`, `providers.module.css:85`) vs raw full-strength `border-color: var(--st-failed)` (`enrichment.module.css:68`, `ai-column.module.css:139`, `enrich/waterfall.module.css:123`). _Why:_ identical-looking delete buttons flash different-saturation red borders. _Fix:_ standardize on the softened `color-mix` idiom (matches `.btn-danger`).
- [ ] **[5 Consistency]** Templates screen bypasses the shared `<Button>`: raw primitive classes `className="btn btn-ghost btn-sm"` (`billing/page.tsx:273`) and `"btn btn-secondary"` (`:125`) where the rest of the file uses `<Button>`; templates renders its selectable card as a raw `<button>` with bespoke chrome. _Why:_ loses the component's unified disabled/loading states. _Fix:_ use `<Button>`.
- [ ] **[5 Consistency]** The **same object — a selectable template card — has two unrelated visual treatments**: templates gallery card (`templates/page.tsx:150`, hover `--shadow-3`, custom outline focus) vs onboarding `TemplatePicker` tile (`onboarding.module.css:205`, surface-2 panel, inset-ring select). _Fix:_ unify into one component.
- [ ] **[6 States]** **Error state is indistinguishable from empty** on sequencers: `SequencerSection.tsx:144` (`runsQuery`) and `PushToSequencerDialog.tsx:155,170` (tables/campaigns) have no error branch — a failed fetch renders the "No pushes yet / No campaigns" empty UI. _Fix:_ add explicit error surfaces.
- [ ] **[6 States]** **Billing "Change plan" grid has no loading skeleton** (`billing/page.tsx:204-228`): while `plansQuery` loads, `plans=[]` renders an empty card body. _Why:_ the summary and invoices cards *do* skeleton, so this one blinks empty. _Fix:_ add a skeleton row.
- [ ] **[6 States]** **Inconsistent error presentation across Phase-4 dialogs:** `ConnectSequencerDialog.tsx:51` and `PushToSequencerDialog.tsx:119` surface submit failures via **toast**, while `InstantiateDialog.tsx:104` and the billing dialogs use an inline `<Alert>`. _Fix:_ pick one pattern (inline `<Alert>` for form submits).
- [ ] **[3 Alignment]** Sequencer action row mixes control heights: a shared `<Button size="sm">` (Push) next to a custom `.linkBtn` (Disconnect, `integrations.module.css:102`, `padding:5px 9px`, no `min-height`). _Why:_ differing heights/weights sit adjacent and read misaligned. _Fix:_ use `<Button variant="ghost" size="sm">` for both.
- [ ] **[5/7]** Nested "card" containers form an ad-hoc third tier: `audit.module.css:49` (`.tableWrap`: full `.card` geometry, **no shadow**), `enrichment.module.css:19` (`.stepCard`: bright `--surface` + panel `--r-md`, no shadow), `enrich/waterfall.module.css:19` (`.step`, same hybrid). _Why:_ neither `.card` (r-lg + shadow-2) nor `.panel` (surface-2 + r-md). _Fix:_ standardize inner cards on `.panel`.

## Positive baseline (no action)

- Primitive **buttons, text inputs/selects, pills/tags/chips, and dialogs are used consistently** across all screens (verified: raw `<button>`s are icon/kebab/tile controls; raw `<input>`s are `file/checkbox/radio` only; all modals use `Dialog`/`ConfirmDialog`; status is always `<Pill>`).
- `EmptyState` (`packages/ui/src/EmptyState.module.css`) is cleanly tokenized (uses `--r-lg`, `--fs-h4`, `--fs-sm`, status-neutral surface) — a good model for the fixes above.
- The `viewBox` grid is near-universally `0 0 24 24`; the color/shadow/radius **token sets themselves are coherent and theme-complete** (dark default + light + explicit toggle). The gap is *adoption*, not the tokens.
